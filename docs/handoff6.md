## 2. Working style, and the standing ground rules

These are settled and confirmed across several sessions. Do not re-litigate
them.

- **Parallel subagents are pre-authorised.** "Spawn parallel subagents freely."
  Give each one a **hard file scope**, and tell it explicitly **not to run any
  writing `git` command** — commits are the coordinator's job. Subagents have
  repeatedly caught real errors in the coordinator's own instructions; when one
  flags a mismatch, check the source rather than overruling it.
- **Commit messages carry the `vX.Y.Z:` prefix**, kept in sync with
  `versionName` in `app/build.gradle.kts`. Messages here are long and explain
  *why*, **including what was wrong before and what was not verified**. Match
  that register — it is the house style and the user reads them.
- **Confirm before any push.** Authorisation is granted per push, explicitly,
  and does not carry over.
- **Do not commit or revert `docs/SafeShadev21/SafeShadev21.ino` or
  `CLAUDE.md`.** Both are modified in the working tree by another session and
  neither is ours. `PRODUCT.md` is untracked and likewise not ours.
- **Verify on the device, not in a preview.** `adb` is on PATH and a Redmi Note
  10S is usually connected. Nearly every genuine fault in the last three passes
  was invisible in the code and invisible in a Compose preview.
- **Say plainly what was not verified.** The user asks for this every time and
  reads it. A screenshot of an affordance is not a test of it.
- **Flag firmware gaps explicitly in the final report.** "Don't silently guess
  and move on."
- **Update `DESIGN.md` in the same pass as any change it describes.** It went
  stale once (naming a symbol that had been deleted) and a design doc naming a
  dead symbol is worse than one saying nothing.
- **Write the next handoff before the session closes**, and include the
  not-verified list in it.

### Design constraints that keep coming back

- **Shady must not read as childish. No speech or thought bubbles.** Absent
  from every safety-critical surface — enforced once in `ShadyHost`, never per
  screen, so a new emergency surface cannot forget the rule.
- **Do not regress:** the GATT operation queue (one outstanding op; everything
  through `enqueue()` / `drainQueue()`), `MESSAGE_CHAR_UUID` is
  Guardian→Companion while `REPLY_CHAR_UUID` is Companion→Guardian, permission
  gating before any scan or connect, `minSdk 26` / `targetSdk 36`.
- **Small fixed sets do not get a slider.** Three named behaviours on a track
  read as a continuum with two invisible stops.
- **Selection is never carried by colour alone** — border weight, fill and ink
  together.
- **Saturation is what separates decoration from status.** Twelve decorative
  accents assigned by `accentFor(key)` (a stable hash); state colours are
  saturated and reserved.
- Brand assets are in `docs/Logo/`. Icon SVGs are in `docs/Icons/`.

## 3. Traps in this repo and this environment

Every one of these has cost real time.

- **Kotlin block comments NEST.** A `/` immediately followed by `*` inside a
  KDoc — writing a directory glob, for instance — opens a comment that never
  closes and fails the build with "Unclosed comment". This has broken the build
  three times. Warn every subagent explicitly.
- **`git add` validates all pathspecs before staging any.** One bad path stages
  *nothing*, and if the next line is `git commit` with no `&&`, it commits a
  partial change with a message describing work it does not contain. That
  produced `d1ea704`. **Always check `git diff --cached --stat` before
  committing, and prefer `&&`.**
- **Never use a regex that spans a KDoc block.** A greedy
  `re.search(r"\n/\*\*.*?\*/\n...", re.S)` matched from the *earliest* `/**` in
  the file and deleted 202 lines of `Color.kt`. Use exact-string replacement
  with an occurrence-count assertion:
  ```python
  assert s.count(old) == 1, (old[:60], s.count(old))
  ```
- **Files are mixed LF/CRLF** (`core.autocrlf` is on). Read as bytes, detect
  `\r\n`, normalise to `\n` for matching, restore on write. Reading with
  `newline=""` while matching a `\n` pattern fails with a bare `AssertionError`
  and no hint why — that happened again this pass.
- **Watch for non-ASCII in the docs when patching them.** A `docs5.py`
  assertion failed this pass because `handoff5.md` contains `1.3×` (U+00D7)
  where the pattern had `1.3x`.
- **The Bash tool's parser chokes on large heredocs.** A ~200-line Python
  script written via `cat > f <<'EOF'` failed twice with "unexpected EOF".
  Use the `Write` tool for the script, then run it.
- **`uiautomator dump` reports app node bounds as though the IME were not on
  screen.** With the keyboard open, a tap at those coordinates lands on the
  keyboard. On the contact editor this silently typed digits into the phone
  field and made a *correct* refusal look like a broken save; it cost about an
  hour. Send `keyevent 4` to dismiss the IME before tapping anything below it —
  `keyevent 111` (ESC) is **not** enough.
- **MSYS path mangling:** `adb shell` paths like `/sdcard/x.png` get rewritten
  to `C:/Program Files/Git/sdcard/x.png`. Prefix commands with
  `export MSYS_NO_PATHCONV=1`.
- **Blind tapping wanders.** A stray tap this pass opened the notification shade
  and a `uiautomator` dump then captured another app's private message text.
  Screenshot before and after a blind tap, and force-stop and relaunch the app
  if the foreground window is not SafeShade.
- **`adb shell input` cannot produce a two-finger gesture**, so no pinch, no
  rotate. Anything multi-touch has to be checked by hand.
- **Put `font_scale` back.** `adb shell settings put system font_scale 1.3` is
  the only way to sweep a raised text size, and an agent once left it at 1.3
  mid-session — every screenshot taken afterwards was at the wrong scale.
- **`Scaffold` measures its `bottomBar` with the full screen height as the max
  constraint.** A `fillMaxHeight()` child drags the whole bar to full height and
  it floats over a blank screen. Introduced twice; `BoardBottomBar` tabs and
  `SosSlot` now carry fixed heights with comments saying so.
- **`Modifier.padding` has no overload mixing `horizontal` with `top`.** Use
  `start` / `end` / `top`.
- **A drawable whose canvas is larger than its artwork makes every layout
  number around it a lie.** Both `splash_emblem` and `brand_tagline` were like
  that. Check `Image.open(p).convert("RGBA").split()[3].getbbox()` before
  trusting a size.
- **A dead flag reads as live state.** `isSendingQuickMessage` and
  `MessagesUiState.isSending` were both defaulted `false`, never set by
  anything, and both had comments and UI written around them as though they
  worked. **Grep for the setter, not the field.**
- **Every SOS test sends real SMS to real people.** Point the emergency contact
  at a spare SIM first. A message carrying a maps link is routinely two
  segments.

## 4. Where the code stands

`versionCode = 7`, `versionName = "2.4.0"`. `assembleDebug` green. **28 unit
tests pass** — `DayStripTest` 8, `DeviceProtocolTest` 15, `PhoneNumbersTest` 4,
`ExampleUnitTest` 1. About 39,000 lines of Kotlin across 101 files.

### 4.1 Architecture, as it actually is

- **`MainActivity`** is the sole Activity. **`SafeShadeApplication`** owns
  **`AppContainer`** (`di/AppContainer.kt`), which builds the repositories on an
  **application-scoped `CoroutineScope`** so alerts, geofence forwarding and
  journey escalation fire with no Activity alive.
- **`ui/vm/SafeShadeViewModel.kt`** is the single ViewModel. **Seven
  repositories** in `repo/`: `AppStateRepository`, `DeviceRepository`,
  `JourneyRepository`, `MessagingRepository`, `ProfileRepository`,
  `SafetyRepository`, `ZoneRepository`.
- **The BLE boundary is `device/`**: `DeviceLink` (the interface),
  `RealDeviceLink`, `DeviceProtocol` (every byte sent to the wearable, unit
  tested — the failure mode of that format is silence, so it needed tests more
  than anything else), and `DeviceCapabilities` (what the app can and cannot
  change on the device; see §10). `BleManager.kt` sits under `RealDeviceLink`.
- **`ConnectionState.Ready` is not `Connected`.** `Connected` means the GATT
  link is up; `Ready` means MTU and service discovery have resolved the
  characteristics. **Every write path must gate on `Ready`.** Before this
  distinction existed, the reconnect re-sync had never once worked.
- **Alerts are a `SharedFlow` of events, not a `StateFlow<Boolean>`.**
  `MutableStateFlow` conflates equal values, so a second fall arriving while the
  first was unacknowledged used to emit nothing and be silently lost.
- **Persistence** is DataStore + Gson (`data/Preferences.kt`,
  `data/local/Dtos.kt`). Every DTO field is nullable with a default because
  **Kotlin defaults never run on the Gson decode path** — `Dtos.kt` says so at
  the top. Enums persist **by name** (`enumOrDefault`), so an older build
  reading a newer store degrades gracefully instead of shifting ordinals.
- **Services**: `LinkService` (foreground BLE link), `JourneyService`
  (journey sampling), `OemReliability` (MIUI-class battery-optimisation
  guidance). `alarms/` schedules reminders and re-arms on boot. `alerts/`
  handles notification, actions and the SMS fallback.
- **Navigation**: `ui/nav/` — `OnboardingNavGraph` and `MainNavGraph` over four
  bottom-bar tabs (**Board**, **Circle**, **Safety**, **Device**) plus Settings,
  and an SOS in the bar itself. Routes are constants in `Routes.kt`.
- **The only network dependency is Open-Meteo** (`WeatherAPI.kt`, Retrofit +
  Gson). The map is **native osmdroid** with a disk tile cache — no key, no
  account, no CDN, and it works offline on a second visit.

### 4.2 The kit — read `ui/board/` before inventing anything

`Controls.kt` (`BoardButton`, `Readout`, `Gauge`, `StubMark`), `Plates.kt`
(`BoardPlate`, `SectionPlate`, `Hairline`), `Way.kt` (the row), `PilotLamp.kt`,
`Status.kt` (`MainsPlate`, `EmptyBay`), `ScreenHeader.kt`, `Expandable.kt`,
`Chips.kt` (`ChipRow` and its suggestion lists), `RichControls.kt`
(`DialControl`, `TimeStrip`, `RangeStrip`, `formatClock`), `Press.kt`,
`ModeVisuals.kt`, and `KitGallery.kt`.

- **`KitGallery.kt` renders the whole kit live in both themes** and is reachable

- **`DialControl`'s `onCommit` fires on release, and anything writing over BLE
  must use it** rather than firing per-frame.
- **`ButtonWeight`** is the button vocabulary: `PRIMARY` (ink), `SECONDARY`
  (`colors.plate` — this is the "dark ash"), `QUIET` (`colors.ground`),
  `ATTENTION` (amber), `COMMIT` (teal), `DANGER` (red). The three hued weights
  take charcoal ink and a W700 label; the achromatic ones stay W600.

  anchors the icon to whichever end the title is at. Fixing this closed two
  separate "the icon is too high" reports at once; see §11.

### 4.3 Icons

`docs/Icons/` holds **102** SVGs (Hugeicons stroke-rounded style).
`tools/gen_icons.py` reads all of them and overwrites
`ui/icons/SafeShadeIcons.kt`, which currently exposes **102** `ImageVector`s
plus `SafeShadeIcons.All` for the gallery. The SVGs are the source of truth; the
generated Kotlin is checked in so the build needs no codegen step.

- **`OPTICAL` in the generator carries a per-slug `scale`, `dx` and `dy`** in
  viewBox units, emitted as a scaled/translated group — **never as an edit to
  the SVG**, so redropping a source file cannot silently undo a correction.
  Three entries today: `check-in` (0.90), `adaptive-mode`
  (0.86, −0.33, −0.57 — the largest artwork in the drop at 21.6 units against a
  set norm of about 18) and `call-after-a-fall` (`dy` only — it measured 13px
  above its neighbours on device).
- **`material-icons-extended` is still a dependency** and dropping it is a real
  APK size win. It is blocked on artwork, not code: `ui/board/ModeVisuals.kt`
  maps eight `PersonaMode`s and eight `DeviceIconType`s onto Material glyphs and
  needs **sixteen distinguishable icons**, of which `docs/Icons` covers one
  (`adaptive-mode`). **Reusing one custom glyph across several modes is
  explicitly the wrong answer** — it destroys the only thing telling the modes
  apart. The wanted list, by Hugeicons name: a circular-arrow reload glyph
  (`arrow-reload-horizontal` / `refresh`) first and most valuable, then `elder`,
  `child`, `bicycle`, a paw/pet glyph, a helmet, a hand/wrist, `backpack-01`,
  `umbrella`, `watch-01`, a pendant/gem, plus `history`, `timer`, `qr-code`,
  `delete`, `user-add`, `walking`, `flash`, `sun`/`moon` and `login`/`logout`
  for the remaining one-off Material usages. The MCP returns icon *names* only,
  so the export has to be done by hand from the Hugeicons site. After the SVGs
  land: run the generator, repoint `ModeVisuals.kt`, drop the dependency from
  `app/build.gradle.kts`, and **the only check that matters is a full
  `assembleDebug`** — a missed usage fails at compile, not at runtime.

## 5. Shady — the full inventory

Because the next pass is Shady-heavy, here is exactly what exists.

**Files:** `ui/shady/Shady.kt` (730 lines — the character itself),
`ShadyPose.kt` (131), `ShadyHost.kt` (77), `ShadyReactor.kt` (616 — tap
reactions), `ShadyStage.kt` (635 — the world at the foot of the Board).

**How it is drawn.** Entirely flat Compose `Canvas` primitives — paths, arcs,
rounded rects, `rotate` / `scale` / `translate`. No images, no Lottie, no Rive,
no 3D anything. It evolves the 8-bit Shady the firmware draws on a 128×64
monochrome OLED rather than porting it.

**`ShadyMood` — 9 values**, mapped from link state by `shadyMoodFor()` so every
screen tells the same story about the same situation: `WATCHING`, `CALM`,
`SEARCHING`, `RESTING`, `CONCERNED`, `OFFLINE`, `CURIOUS`, `LOOKING`,
`DUMBFOUNDED`.

**`ShadyPose`** is a momentary override layered on top of a mood — `offsetX/Y`,
`rotation`, `scaleX/Y` (squash and stretch), `eyes`, `mouth`, `handsUp`,
`facingLeft`, `flourish`, `gazeX/Y`. Every field has a neutral default, and
offsets are fractions of the drawn size rather than dp so an action looks
identical at 56dp in a card and at 104dp on the stage. **Body space, not screen
space:** `facingLeft` mirrors the character, so `gazeX` is relative to the body
while `offsetX` is applied outside the mirror.

**`ShadyReactor` — tap reactions, in two sets sized for their surface.** The
rule it exists to serve is **never the same reaction twice in a row**.
- `SUBTLE` (12, for the status card): `blinkAndBeam`, `littleHop`,
  `curiousTilt`, `quickWave`, `sparkle`, `ponder`, `raisedBrow`, `nod`, `peer`,
  `shiver`, `doubleTake`, `yawn`.
- `BOLD` (14, for the stage): `startle`, `spin`, `cheer`, `tumble`, `delight`,
  `wobble`, `backflip`, `sneeze`, `hiccup`, `trip`, `shakeOff`, `nodOff`, `bow`,
  `sidestep`.

Reactions are **keyframed by hand rather than expressed as a spring**, because
squash-and-stretch has to be *timed* — the compression before a hop and the
stretch at the apex are the whole effect, and an interpolator that merely gets
from A to B smoothly loses them. Keep that when adding more.

**`ShadyStage` — 16 idle behaviours**, weighted so walking is the connective
tissue and the rarest beats stay rare: `amble`, `lookAround`, `hop`,
`stretchAwake`, `sitAndSwing`, `doze`, `think`, `peekFromEdge`, `chase`,
`tripAndRecover`, `doubleTake`, `sneeze`, `examineFloor`, `waveAtYou`, `shiver`,
`noticesYou`. It stands on the bottom navigation bar's top rule and treats it as
**ground**. There is a beat of stillness (500–1900ms) between actions, without
which the character reads as frantic rather than alive. Two beats face out of
the screen; being *caught watching you* is the rarest and only works while it is
still possible you imagined it.

**`ShadyHost` is the only place Shady may be drawn**, and the only place the
suppression rule lives: when an emergency is live Shady is **removed from the
composition entirely**, so it cannot animate, cannot be read by a screen reader
and cannot consume frames while a countdown runs. Screens never call `Shady`
directly.

**Notes for the 3D pass.** "Subtly 3D" has to be earned inside the same draw
code: a light direction and consistent shading, a contact shadow that reacts to
the hop, a little perspective on the body's silhouette as it turns. Two hard
constraints stay: **no speech or thought bubbles**, and **nothing that costs
frames on the emergency screens** — which `ShadyHost` already guarantees by
construction. And "interacts with other materials, pets, tech, appliances,
nature" means the stage needs *props* it can share the ground with; today the
only thing it interacts with is the rule it stands on and the unseen something
it chases off the edge and never catches.

## 6. The adaptive-mode page

**Where it lives:** `ui/screens/device/ModePickerScreen.kt` (883 lines, a
`HorizontalPager` of mode cards) with `ModeScenes.kt` (740 lines — a
hand-animated `Canvas` scene per mode, using Shady) and `ui/board/ModeVisuals.kt`
(66 lines — the `PersonaMode` → icon map). The row that opens it is on
`DeviceScreen.kt` and now draws a fixed `adaptive-mode` glyph rather than the
selected persona's icon.

**The user's verdict:** UI, arrangement and spacing are still terrible, and a
user should be able to see **more information about each mode**.

**Where the content comes from: pitch-deck slide 13**, which is a per-mode table
of *Algorithm Adaptation*, *UI Changes* and *Priority Features* — e.g. Elderly
"sensitive fall thresholds (2.5g impact) / large fonts, simplified UI / fall
detection, medication reminders, night bathroom lighting"; Helmet "high-speed
impact (6g+ threshold) / minimal distraction UI / concussion alerts, worker
check-ins". That is exactly the "more information about the modes" the user is
asking for, already written and already public in the deck. Wrist is flagged in
the deck as depending on the planned health sensors.

**What the app already knows:** eight `PersonaMode`s including `AUTO` (which is
the fresh-install default, matching the firmware's fresh-boot default), the wire
format `EXT MODE:<NAME>`, and that ELDERLY/KIDS/PET/HELMET are **guardian-locked**
— the app marks them with a visible seal and explains that mode switching and
the Safety menu are hidden on the wearable in those modes. `AUTO` renders as a
hero plate with **no icon at all**, which is why one attempted fix last pass was
invisible on device.

- **`StubMark`** ("Representative data, not live") is used in exactly one place —
  `SilentSosScreen` — because the firmware has no silent-SOS path.

  this system can honestly draw a delivery receipt.** Closing that needs a
  firmware change and belongs with the relay gap.

## 9. Known bugs, rough edges and deliberate debt

### The one real defect of this pass, and why it matters going forward

**The quick-message tick claimed a send had succeeded when it had failed.** It
was set on the tap and cleared after 1400ms regardless of outcome — and with
nothing paired and no SIM number stored, which is what a fresh install and this
test phone both are, **every send fails**. The confirmation was watched, filmed
and written into the previous handoff as verified without anybody asking what it
was confirming.

`MessagingRepository` had returned a user-facing `SendResult` the whole time,
with a `Failed.reason` written to be shown to a person, and its own comment says
a message that reports success and reaches nobody is worse than one that reports
failure. **Every layer above it discarded the value.** Fixed by threading
`SendResult` up through ViewModel → nav → row; `DESIGN.md` now carries "Don't
confirm an action before its result is known" as a rule.

This is the trap to watch through the whole backend pass in §1.5: a login, a
database write, an email send and an evidence upload are all things that can
fail quietly, and the app's habit until now has been to draw the happy path.

### Carried debt, deliberate

- **`OptionWay` lives in `ui/screens/safety/SafetyCommon.kt`** and is imported
  from `device/DeviceSettingsScreen.kt`. It is `internal`, so it is legal, but
  it belongs in `ui/board/` with the rest of the row kit. Carried for two
  passes.
- **The check-in interval's shared constants live in
  `device/RemindersScreen.kt`** as `internal` declarations that
  `DeviceSettingsScreen.kt` reads — the same smell as `OptionWay`: two screens
  sharing through one of themselves rather than through the kit.
- **`ChipRow` has no visible focus ring** (`selectable(indication = null)`), so
  tabbing or an IME "Next" into the row lands focus invisibly. Flagged three
  passes ago.
- **The back chevron's touch target overlaps the title's first 8dp.** The slot
  reserves 28dp and the button is a 48dp box offset −12dp, so it spans −12 to
  36 while the title starts at 28. Harmless today because no header title is
  clickable; it stops being harmless the moment one is.
- **`WhyDisclosure` takes no count.** It wraps prose rather than a set of
  options, so a number would mean nothing — but it is the one collapsed thing in
  the app without one and somebody will notice.
- **The empty-state magnifying glass** overlaps the top-right of Shady's body
  and its handle runs behind it. It reads as "held" and balances the antenna,
  but it was not the drawn intention.
- **Quiet hours are not persisted** (see §7).
- **`material-icons-extended` is still a dependency** (see §4.3).
- **The stored emergency contact on the test device has eleven digits after the
  country code** and cannot be repaired from here — `…66006` and `…60065` are
  both plausible ten-digit numbers and picking one would be inventing an
  emergency contact. The app says so and refuses to save until it is corrected.
  **This needs the owner, not a guess.** Every SMS and call that contact ever
  received from this app went to a truncated number.

## 10. Firmware — what the app knows the firmware owes it

Nothing in the last three passes touched the firmware. Verified by reading
`SafeShadev21.ino` directly and cross-checking against what the app sends.

1. **No wire format exists for relaying a phone-originated SOS over the
   wearable's cellular gateway.** This is the single biggest app↔firmware gap.
   A phone-raised SOS currently reaches a contact only if the *phone* has signal
   and the `SEND_SMS` grant; on a wearer whose phone is dead but whose wearable
   has a cellular link, the alert does not go out. Closing it needs a new EXT tag
   and a handler — something like `EXT SOSRELAY:<e164>,<text>` — **with an ack**,
   so the app can report per contact honestly rather than optimistically. It is
   also a precondition for the deck's "notifies independently" promise (§7).
2. **`CMD_FIND` has no real locate path.** The app's intent is a low-key locate:
   ring, show an RSSI proximity meter, show last known location. The firmware
   drops the device onto the full `SCREEN_SOS` — blinking banner, siren, red LED
   ring — sends no ACK, dispatches no alert, and clears **only** when somebody
   physically taps the device. There is no timeout, and the app has no way to
   know the siren stopped, so its "ringing" banner must be dismissed by hand and
   says so. Suggested: a `SCREEN_LOCATE` with a short repeating chirp, a visible
   "Tap to stop", a ~30s auto-timeout, and an ACK.
3. **`CMD_FIND` shares `WEATHER_CHAR_UUID` with weather.** A weather payload
   written while the device is on the alarm screen is parsed by the weather
   parser. The app works around it (`DeviceRepository.isRinging` suppresses all
   automatic weather sync while ringing) but `CMD_FIND` belongs on `EXT_CHAR`
   like every other command.
4. **Eight on-device settings have no BLE write path at all** — `ledsEnabled`,
   `displayContrast`, `flipDisplay`, `homeTickerEnabled`, `masterVolume` (the
   chime volume, distinct from `sosVolume`, which *is* wired), `bootChimeEnabled`,
   `notifChimeEnabled`, and **the Do Not Disturb toggle itself** (only its
   start/end hours ride on `EXT QUIET`). They are rendered read-only with the
   wearable's own menu path. If firmware adds EXT tags, moving a row from
   `DeviceCapabilities.deviceOnly` to `.synced` is a one-line change. **DND is
   the one to fix first** — a settable schedule behind an unsettable master
   switch is a strange half-capability.
5. **There is no silent SOS path.** An SOS always sounds the siren and takes the
   screen. The app has a silent-SOS affordance for the women's-safety persona
   (SMS + location, no sound, no visible change) and marks it representative
   until firmware gains a quiet path.
6. **Torch is the only LED pattern that calls `setHeadlamp(true)`**, so choosing
   any other pattern silently switches the wearable's front lamp off. The app now
   says so in Torch's description. Is that coupling intended?
7. **The Police light swatch runs at 600ms per half against the firmware's
   300ms**, deliberately, for WCAG 2.3.1 — at the real rate it alternates
   saturated red and blue 3.3×/second and the guideline draws its line at three,
   with a stricter threshold for red. If the firmware timing changes, the comment
   in `LightsScreen.kt` needs updating.

**Confirmed working, no action needed:** `MODE_AUTO` and all eight modes;
the 11-field `HEALTH_CHAR` in the firmware's exact positional order with commas
stripped from all nine free-text fields and `organDonor` as `1`/`0`;
guardian-locked modes; message/reply directionality; `ALERT_CHAR`'s payload.

**When the pass finally begins:** `arduino-cli` is installed locally, the
mainboard must build as `XIAO_ESP32C3` with the `no_ota` partition scheme, and
`docs/SafeShadev21/SafeShadev21.ino` is being edited by another session —
**coordinate before touching it.**

## 11. Judgement calls not worth re-litigating

`DESIGN.md` holds the design system itself; these are the decisions a reader
might otherwise reopen. Do not duplicate `DESIGN.md` into a future handoff —
point at it.

- **Colour on a button.** Three hued weights exist where `DESIGN.md` once said
  danger red was the only one. The rule was weakened deliberately: a screen with
  four identical charcoal plates makes the one that matters findable only by
  reading. The saturation rule still separates these from the twelve decorative
  accents.
- **"Amber" means `inkAttention`, not `lampAttention`.** Brand amber on the bone
  panel measures about 1.9:1. Every "make it amber" request resolves to the ink
  token unless the amber is a *fill*, in which case charcoal is the only label
  colour that measures — in both themes, because the glasses do not darken for
  the night panel.
- **"Dark ash" is `ButtonWeight.SECONDARY`** (`colors.plate`). A request for it
  on a button that is already `SECONDARY` needs no change; changing it to
  `QUIET` is wrong and was reverted once.
- **A way's icon centres on its title's line, not on its row.** Two separate
  "nudge this icon down" reports turned out to be one layout fault: the icon was
  anchored to the top of the *row*, which is right when a detail line puts the
  title at the top and wrong when there is no detail and the text is centred —
  worst where the trailing control is a 48dp toggle. Only one of the two icons
  needed anything done to its artwork. **Measure rows before attributing an
  alignment complaint to the glyph.**
- **`OPTICAL` corrections live in the generator, never in the SVG** (§4.3).
- **The red GPS glyph** was asked for and is the one place a state hue sits on
  something that is not reporting state. It is named in `DESIGN.md` so that
  finding it in the source is not read as a licence.
- **Which durations became sliders.** Fall countdown (15/30/45/60s, a linear
  ramp) and check-in interval. Fall sensitivity stays rows — Low/Medium/High are
  named behaviours. The Silent SOS staged-call delay stays rows — 10s/30s/1m/5m
  is logarithmic and each option has to explain what staging means.
- **The map's coordinate fields were deleted** despite a KDoc arguing they must
  never be hidden behind a map failure. That argument was written against the old
  WebView, which could fail to attach its tap handler and leave the map inert
  with no tell; the native map attaches its handler at construction.
- **The Device bank's mode row takes a fixed glyph.** It used to draw the
  selected persona's icon, so a row named "Adaptive mode" showed a backpack. If
  the varying icon is ever wanted back it is one line in `DeviceScreen.kt` — but
  note `AUTO` draws no icon at all.
- **Title Case** is the ordinary kind: principal words capitalised, articles and
  short prepositions left alone unless they lead. "Connect to the Device", not
  "Connect To The Device". Title Case is for **prominent buttons only**.
- **112's label is "112 – All Emergencies"** — the user wrote "All Emergency";
  the plural was kept as a grammatical correction and flagged to them.
- **The intro wordmark was already the right font** (Archivo W800); the fault was
  `letterSpacing = -0.03em`. And the intro's proportion problems were in the
  drawables' transparent margins, not in any layout constant. Both recorded so
  nobody spends that time again.
